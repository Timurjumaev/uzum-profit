# Снабжение: от закупки до приёмки Uzum

Эта статья объясняет, как в программе вести путь товара из Китая (или местной закупки) до сдачи на склад Uzum. Каждый шаг —
один экран; себестоимость пересчитывается сама на каждом шаге.

У закупки три статуса, и они не нажимаются вручную — определяются по сделанной работе:

| Статус | Когда |
|---|---|
| **В пути** | закупка сохранена, товар ещё не посчитан |
| **На моём складе** | товар посчитан, он у вас на руках |
| **В Uzum** | отправлен на Uzum и связан с поставкой |

## 1. Ввод закупки

**Закупки → Новая закупка.** Выберите товары (SKU) и количество. Если в одном заказе разные товары, у каждой строки укажите
**сумму строки** из 1688 (не цену за штуку). Внизу — **«Всего оплачено»**: сумма, реально списанная со счёта (CNY, USD или
UZS), и курс: курс ЦБ или ваш собственный. Трек-номер необязателен.

Если товар уже у вас (местная закупка), отметьте **«Товар у меня»** — карго не ожидается.

Сразу после сохранения закупка **В пути**, видна ориентировочная себестоимость «1 шт. ≈ … сум» (карго ещё не введено —
с отметкой «Оценочно»).

## 2. Деньги за карго

**Закупки → Деньги за карго.** Когда карго-компания пришлёт счёт, введите его здесь:

- **У каждой закупки своё карго** — впишите сумму в строке (кг необязательно).
- **Одна коробка — несколько закупок** — отметьте закупки и нажмите **«Объединить в одну коробку»**: общая сумма делится по
  штукам, любую долю можно изменить вручную (остаток снова по штукам).

После ввода карго отметка «Оценочно» исчезает, себестоимость обновляется.

## 3. Пересчёт

Когда товар пришёл — на странице закупки **«Пересчёт»**: пришедшее количество и брак по каждой строке. Если всё пришло —
**«Пришло всё»**. Если пришло меньше и продавец вернул деньги — **«Сумма, возвращённая продавцом»**. Себестоимость брака
распределяется на годные единицы.

Если часть придёт позже — **«Разделить закупку на две»**: ожидаемая часть станет отдельной закупкой.

После пересчёта закупка переходит в статус **На моём складе**.

## 4. Мой склад

**Склад → Мой склад.** Остаток на руках по SKU и его стоимость по себестоимости. Здесь можно:

- **Перевести на другой SKU** — например, если ошиблись цветом; переносится вместе с себестоимостью.
- **Брак, найденный позже** — списывается, в расчёте прибыли появляется строка «Убыток от брака».

## 5. Отправка на Uzum

**Мой склад → Отправка на Uzum.** Выберите магазин — появятся все его SKU с моего склада с полным количеством. Уменьшите
количество или уберите лишние строки и нажмите **«Скачать Excel»**. Файл в шаблоне кабинета Uzum (штрихкод, себестоимость,
количество) — загрузите его при создании поставки в кабинете. SKU без штрихкода в файл не попадает (будет предупреждение).

Сразу после скачивания единицы **«Отправляются»** — резервируются на моём складе. Когда поставка создана в кабинете и
пришла в программу, отправка **связывается сама** (если подходящих поставок несколько — выберите из списка). После этого
закупка **В Uzum**. Если отменить отправку или поставка отменена, единицы возвращаются на мой склад.

## 6. Расхождения при приёмке Uzum

**Отправка на Uzum → Расхождения приёмки.** После приёмки поставки Uzum отправленное количество сравнивается с принятым.
Расхождение видно в блоке **«Требует внимания»** на главной.

**Если принято меньше** — выберите одно из двух:

- **«Uzum потерял»** — единицы попадают в **список недостач**. Затем меняете статус: **Нашлось**, **Компенсировано** (с
  суммой, выплаченной Uzum) или **Списано в убыток**. Убыток сверх компенсации или списанный — отдельная строка в расчёте
  прибыли («Потери при приёмке Uzum», F52).
- **«Я ошибся при подсчёте»** — пришедшее количество в закупке исправляется, себестоимость пересчитывается.

**Если принято больше** — при открытой недостаче по этому SKU **«Нашлось»** (недостача закрывается), иначе **«Увеличить
количество»** (количество в закупке увеличивается).

Если по недостаче приёмки есть штраф Uzum (C000007), он виден в карточке расхождения.

## Старые закупки

Прежние закупки с этапами (оплачено, на складе в Китае, в пути, прибыло…) не удаляются: статус определяется по их датам —
принята — **На моём складе**, отправлена на Uzum или закрыта — **В Uzum**, остальные — **В пути**. Их даты используются для
расчёта срока «В пути» (ожидаемая дата подсчёта).
